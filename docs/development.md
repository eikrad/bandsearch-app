# Development guide

Everything you need to work on Bandsearch locally beyond the README's quick
start: the desktop app, calling the API by hand, checks, translations and
golden runs. Hosting and operating the API is in [deployment.md](deployment.md).

## Prerequisites

- Node.js 26.12.1+ (the version in `.nvmrc`) and npm. npm is the only package
  manager: `package-lock.json` is the one lockfile, and `devEngines` in
  `package.json` refuses other package managers.
- A Scaleway Generative APIs key (`SCW_SECRET_KEY`) and a Brave Search API key
  (`BRAVE_API_KEY`). The API refuses to start without either.
- For `npm run lint` (and so `npm run ci` and the pre-commit hook): `ruff` and
  `black`, from a repo-local `.venv` or on the `PATH` (`scripts/lint-py.sh`).
  They check the placeholder `main.py`/`pyproject.toml`, which are not part of
  the application.
- For the desktop app: [Rust](https://rustup.rs) and the platform build tools
  below.

## Running the API

```bash
npm install
cp .env.example .env        # add SCW_SECRET_KEY and BRAVE_API_KEY
npm run dev                 # http://localhost:3001
```

Account data goes to `bandsearch.db` (SQLite) by default; see
[deployment.md § Storage](deployment.md#storage) for the other backends.

### Calling it by hand

The simplest call holds the request open until the answer is ready:

```bash
curl -X POST http://localhost:3001/recommendations \
  -H "content-type: application/json" \
  -d '{"query": "I like Alcest and Agalloch"}'
```

The app instead starts a **search job** and follows it, which survives a
dropped connection ([ARCHITECTURE.md § Search jobs](architecture/ARCHITECTURE.md#search-jobs)):

```bash
curl -X POST http://localhost:3001/recommendations/jobs \
  -H "content-type: application/json" \
  -d '{"query": "I like Alcest and Agalloch"}'          # → {"jobId":"…"}
curl -N -H "accept: text/event-stream" http://localhost:3001/recommendations/jobs/<jobId>
```

When all 200 job slots are running, a search from another user is refused with
`503 search_capacity_exceeded`; retry later. Replacing your own running search
stays possible.

## Desktop app (Tauri)

```bash
npm run desktop             # opens a native window and starts the API itself
```

Tauri expects a Node sidecar next to the Rust crate (`bundle.externalBin`). For
local development, link your system Node once (the file is gitignored):

```bash
# Linux / macOS — the host triple comes from: rustc -vV | grep ^host
ln -sf "$(which node)" apps/desktop/src-tauri/binaries/node-$(rustc -vV | sed -n 's/^host: //p')
```

On Windows, copy `node.exe` to
`apps/desktop/src-tauri/binaries/node-x86_64-pc-windows-msvc.exe` instead.

### Platform prerequisites

**Linux:**

```bash
# Arch / Manjaro
sudo pacman -S webkit2gtk-4.1 libappindicator-gtk3 librsvg

# Debian / Ubuntu
sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
```

**macOS:** Xcode Command Line Tools (`xcode-select --install`).

**Windows:** [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
with the **Desktop development with C++** workload. WebView2 is built into
Windows 10 1803+ and Windows 11.

### Where the app keeps its settings

Settings saved in the app (Scaleway and Brave keys, optional Turso database,
API endpoint) are written to `bandsearch/config.json` in the OS config
directory. A Gemini key stored by an earlier version is removed, since the API
no longer uses Gemini.

| OS | Path |
|----|------|
| Linux | `~/.config/bandsearch/config.json` |
| macOS | `~/Library/Application Support/bandsearch/config.json` |
| Windows | `%APPDATA%\bandsearch\config.json` |

The local sidecar runs only while no remote API endpoint is set in Settings.

### Adding a Tauri command

Tauri rejects any app command the window has no permission for. To add one:

1. Write the `#[tauri::command]` function in `apps/desktop/src-tauri/src/main.rs`.
2. Add its name to the list in `apps/desktop/src-tauri/src/app_commands.rs`. That
   one list registers the command and generates its `allow-<name>` permission.
3. Grant `"allow-<name-with-dashes>"` in `apps/desktop/src-tauri/capabilities/default.json`.
4. Build once (`cargo check` in `apps/desktop/src-tauri`) and commit the
   regenerated `gen/schemas/`. When you remove a command, delete the ignored
   `apps/desktop/src-tauri/permissions/autogenerated/` first: Tauri never deletes
   its generated files, so a stale permission would otherwise stay in
   `gen/schemas/`.

Forgetting step 3 fails the build; `npm test` and `cargo test` check the same.

## Checks

```bash
npm test               # all workspace tests
npm run ci             # lint + typecheck + test
npm run test:e2e       # Playwright smoke tests (starts the API and a static frontend)
npm run test:e2e:live  # also the @live specs against the real pipeline (slow)
```

The pre-commit hook (installed by `npm install`) runs lint, typecheck and
tests. CI runs them on `ubuntu-latest` and `windows-latest`, plus the
Playwright smoke tests. [CONTRIBUTING.md](../CONTRIBUTING.md) has the details.

## Translations (English, German, Danish)

The app's text lives in `apps/desktop/src/i18n/locales/`. English (`en.json`)
is the source; German and Danish are drafted by a model and reviewed by a
person. The chat screen and the privacy policy text are still English only
(#329, #349).

```bash
npm run i18n:translate          # draft new, changed and missing strings (de, da) via Scaleway; or: -- de
npm run i18n:review -- da       # walk the drafts one by one: accept, edit, reject; the glossary comes first
npm run i18n:check              # what CI checks: missing keys, placeholders, plural forms, glossary words
```

- **New or changed text:** add it to `en.json` (a key the views use must exist
  there, or the typecheck fails), then run `i18n:translate`. CI fails until
  every language has the key.
- **Glossary** (`apps/desktop/src/i18n/glossary.json`): fixed words for key
  terms, names that stay as they are, and the tone per language (German "du").
  Translations must use them; the check enforces it.
- **Review state** (`apps/desktop/src/i18n/review/`): `draft` or `reviewed` per
  string, with the English it was made from. A reviewed string is never
  redrafted unless its English changes. Drafts are shown in the app.
- `I18N_MODEL` picks the model (default `mistral-medium-3.5-128b`); the key
  comes from `SCW_SECRET_KEY` or the repository's `.env`.
- **Another language:** add it to `SUPPORTED_LANGUAGES` and `LANGUAGE_NAMES`
  (`apps/desktop/src/i18n/i18n.ts`) and `TARGET_LANGUAGES`
  (`apps/desktop/scripts/i18n/catalog.ts`), give every glossary term a rendering
  and a style line, then run `i18n:translate` and `i18n:review`.

Chat replies are not UI text: they follow the language of the user's message
(`services/api/src/replyLanguage.ts`).

## Measuring recommendation quality

With the API running:

```bash
npm run golden -w services/eval -- --label baseline --repeat 3   # three runs of one setup
npm run dashboard -w services/eval                               # rebuild the comparison dashboard
npm run calibrate -w services/eval                               # check the LLM judge against human labels
npm run routing -w services/eval                                 # check the follow-up turn router
```

Metrics, replay mode, constraints, run history and the dashboard are described
in [evaluation.md](evaluation.md).
