# Spike: the real frontend in a throwaway Android build (#319)

Throwaway spike for map #314. The branch `research/android-spike` is the
evidence and is **never merged**. Written 2026-11-20 from `origin/staging`
(`7ad4268`), following the amended step order from the shell research (crate
split → `tauri.android.conf.json` → module gating → `tauri android init`).

Every row below comes from a command run in this session. "needs owner" marks
what could not be checked without the invite code or a human gesture.

**Limits of this run.** The phone was locked for most of the session (the
keyguard came back at about 18:23 UTC and stayed until the end). The visible
tests (first paint, keyboard, back, external link) ran in the unlocked window
from 18:20 to 18:23 UTC. The cold start with screenshots, rotation, safe-area
with the IME closed under `viewport-fit=cover`, and the release-build panic were
therefore not observable, and are listed under "needs owner".

**Not predicted by the research, found by the spike:**

1. **The ACL denies every app command without a permission.** Only
   `llm_config_status` and `save_llm_api_key` have permissions
   (`permissions/llm.toml`). From the phone (CDP `invoke`):
   `complete_onboarding not allowed. Command not found`, and the same for
   `save_api_endpoint_url`, `save_brave_api_key`, `clear_turso_config`,
   `install_update`. So "Skip for now" on the welcome screen never persists, and
   the Settings endpoint override (#159) cannot be saved. The capability file is
   shared with desktop, so desktop is very likely affected too (**not run on
   desktop** in this spike: verify before acting).
2. **`openUrl` is not allowed either.** `opener:allow-default-urls` is only a URL
   scope. Without `opener:default` (or `opener:allow-open-url`) the call fails:
   `opener.open_url not allowed. Permissions associated with this command: opener:allow-open-url, opener:default`.
   `openExternalLink` then falls back to `window.open`, which on Android
   **navigates the app's own WebView to the external page** (see the external-links row).
   The spike added `opener:default` (commit `fix(spike): grant opener:default …`).
   Same capability file on desktop, so desktop links may take the fallback path too (not run on desktop).
3. **First run shows the Scaleway-key welcome screen** on Android (`#/welcome`,
   "Add a Scaleway API key once on this device…"), as the reviewer predicted.
4. **stdout/stderr reach logcat** under the tag `RustStdoutStderr` (Tauri
   redirects them), so `eprintln!` is visible in debug builds.

## What the owner must do

1. Install `~/Android/spike/Bandsearch_0.4.5_arm64_debug.apk` (or the
   throwaway-signed release APK; the two have different signatures, so
   uninstall first: `adb uninstall app.bandsearch`).
2. First run: on the welcome screen choose "Skip for now". Expect the bug from
   finding 1: skip is not persisted, and the welcome screen returns on the next launch.
   Or enter any text as the key, which persists and gets you to login.
3. Register with the invite code, send one chat message, tap a Bandcamp/Spotify
   link (expect the browser or app), and press both export buttons (expect
   nothing) and Import (check that a `.json` file is selectable).
4. Force-stop (`adb shell am force-stop app.bandsearch`) and relaunch: still signed in?
5. Update with the same key: run `adb install -r` with a rebuilt APK signed by the same
   throwaway key (`~/Android/spike-keys/spike-throwaway.p12`, alias `spike`, password in the spike
   report) and check that you are still signed in.
6. Release panic: on a fresh install of the release APK, enter `spike-panic` as
   the key and check `adb logcat -s RustStdoutStderr DEBUG`.
7. Leave the API idle for more than 15 minutes, launch, and watch the Connecting screen (the screenshot series).
8. Rotate the phone, and try a back *gesture* (predictive back), and 3-button mode.

## Review amendments (Opus, 2026-11-20)

An independent review re-checked the artifacts and the committed source (read-only, phone not touched). The rows above stand except where this section corrects them. **Where it differs, this section wins.**

1. **Finding 1 (ACL) is a pre-existing desktop bug, and its root cause is different.**
   - Cause: `build.rs` is plain `tauri_build::build()`, but `permissions/llm.toml` defines permissions, so tauri-build 2.7.6 (`src/acl.rs:421-426`) creates the app ACL manifest `__app-acl__`. With it, tauri 2.12.7 (`src/webview/mod.rs:2080`) rejects every app command without a permission. It is not the shared capability file.
   - It has been so on **desktop (staging and main) since `permissions/llm.toml` landed (b28c95d, 2026-05-12)**, independent of Android. Debug builds say `<cmd> not allowed. Command not found`; release builds say `Command <cmd> not allowed by ACL`.
   - The list was incomplete: `save_turso_config` is denied as well. Only `llm_config_status` and `save_llm_api_key` are allowed.
   - What breaks for users: `complete_onboarding` (`desktopSettings.ts:95`, error swallowed, so "Skip for now" never persists), `save_brave_api_key` (:201, red error in Settings), `save_turso_config` (:242), `save_api_endpoint_url` (:284, so the endpoint override of #159 cannot be saved), `clear_turso_config` (:307), `install_update` (`startDesktopBrowserApp.ts:153` to `updateNotification.ts:92-94`: the update banner's Install button does nothing, only a `console.error`; in-app update has never worked since d3e23a8, 2026-08-30).
   - Desktop reproduction: on staging run `npm run tauri dev` in `apps/desktop`; in the devtools console `window.__TAURI_INTERNALS__.invoke("complete_onboarding")` rejects, `invoke("llm_config_status")` resolves.
   - Fix direction: one `[[permission]]` per command plus an entry in `capabilities/default.json`, and a test that every `generate_handler!` command has a permission.
2. **Opener.** The minimal correct capability is `opener:allow-open-url` plus `opener:allow-default-urls` (tauri-plugin-opener 2.7.3: `opener:default` also grants `reveal-item-in-dir`, which nothing uses). On desktop, `openUrl` is denied as well, so `openExternalLink.ts` always takes the `window.open` fallback there (desktop runtime effect not run).
3. **Signing.** The APK carries v1, v2 and v3 signatures (`apksigner verify --min-sdk-version 23`). Plain `verify` shows v2 as false only because it checks the scheme minSdk 29 needs. "v3 only" above is wrong.
4. **Debug APK size.** 264,000,889 B, with about 124.3 MB of dead space between zip entries (a leftover copy of the debug `.so`). The clean build is 139.7 MB.
5. **Back.** `has died: cch CRE` means the process was a cached-recent one, i.e. the task was still in recents. This fits "moved to the background, then killed by OPPO/ColorOS memory management" better than "activity finished". Either way the next launch is a cold start, so do not rely on a warm resume. Tauri's `AppPlugin` walks the WebView history, then falls to the platform default (background on Android 12+). The spike also found a real defect: the pre-router entry `https://tauri.localhost/` costs one dead back press, because `createHashRouter.navigate` pushes via `location.hash =`; initial and auth redirects must use `location.replace`. `docs/design/UI_GUIDELINES.md` (lines 386-389) says "Without handling, Tauri simply closes the app on back": that sentence is wrong.
6. **Cold start: the keyguard explanation is not sound.** The 80 s on `#/connecting` proves nothing (the polling budget in `waitForApi.ts` is 90 s). Two real findings from reading the code against the measured 37 s: (a) `startDesktopBrowserApp` awaits `session.start()`, and with it the first `/auth/status`, **before** `reactApp.mount()`, and `index.html` has only an empty `#root`, so during a held cold wake the user sees a **blank page** for about 37 s, not the Connecting screen; (b) `getAuthStatus` (`authApiClient.ts:84`) has no fetch timeout, so a hung request blocks the loop and the budget is only checked between attempts. This is inferred from the code plus the curl, not observed on the phone, and it affects desktop with a remote endpoint as well. The screenshot series stays needs owner.
7. **Not tested, mark as needs owner:** `localStorage` ("works" above means only "empty before login"), the chat composer with the soft keyboard (only the login inputs were tested), and the Chat, Saved and Settings layouts at narrow width (only login and register have screenshots).
8. **Template leftovers:** the manifest still has the leanback feature and `LEANBACK_LAUNCHER` (the research asked to drop them, with a manifest-assertion test). The committed `gen/schemas/acl-manifests.json` is the Android flavour (no `updater` key), so a desktop build rewrites it; production must decide how to handle per-target schema churn.
9. **Checked and confirmed:** release APK `apksigner verify`, `zipalign -c -P 16 4`, `aapt2 badging` (`app.bandsearch`, 4005, 0.4.5, minSdk 29, target/compile 37, arm64-v8a only), all four LOAD segments `Align 0x4000`, `allowBackup=false` with `dataExtractionRules`, AGP 9.5.2 in both places, Gradle wrapper 9.6.1, no `ndkVersion`, the diff minimal for a spike, desktop `cargo check --locked` passes on the branch, and the three committed screenshots and the branch contain no personal data or secrets.
